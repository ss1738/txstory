# TxStory usability evaluation kit

This kit compares how well people understand real Ethereum transactions using
**TxStory** versus the **source block explorer** (eth.blockscout.com). It is kept
separate from engineering verification (`../VERIFICATION.md`).

**Status: Evaluation kit ready; human usability remains unmeasured.** No
participant sessions have been run. `RESULTS.md` is intentionally empty.
`WALKTHROUGH.md` is an expert walkthrough by the developer, not a participant
study.

## Contents

| File | Purpose |
|---|---|
| `PROTOCOL.md` | Design, measures, and success criteria. Written before any observation. |
| `TASKS.md` | Neutral question wording, read aloud, identical for both interfaces |
| `ANSWER_KEY.md` | Answers, scoring rules, misunderstanding codes, and documented ambiguities |
| `answer-key.json` | Machine-readable facts, generated by `verify_answer_key.py` |
| `verify_answer_key.py` | Derives the facts from the raw captured RPC data, independently of TxStory, and checks them against explorer state changes. Needs the captured recordings (see below). |
| `FACILITATOR.md` | A non-coaching script |
| `PARTICIPANT.md` | What participants are told, including the data they do and do not give |
| `make_session_sheets.py` | Counterbalanced per-participant link sheets and pre-filled result CSVs |
| `results-template.csv`, `issues-template.csv` | Column layout for answers and for problems or comments |
| `score.py` | Descriptive summary against the pre-set criteria. `--self-test` uses synthetic in-memory rows only. |
| `WALKTHROUGH.md` | The expert walkthrough record and the fixes it led to |
| `RESULTS.md` | The place for real results. Empty. |

## Captured recordings (not in this repository)

The study's TxStory condition uses ten real mainnet transactions. Their captured
provider responses are **not distributed** with the repository, because their
redistribution terms are unresolved (see `../DATA_PROVENANCE.md`). Running the
study as designed needs a local copy of those recordings, kept outside the
repository:

- `CAPTURED`: a directory containing the `ethereum-<hash>.json` recordings for
  the ten task transactions;
- `EVIDENCE`: a directory containing `blockscout-state-changes-0x55696a27.json`.

`answer-key.json` (the derived facts) is in the repository and does not need
them.

Without the recordings you can still prepare the kit. The two ways to run the
TxStory condition are then:

- **Live mode:** TxStory fetches the same public transactions live. The T5
  answers change, because the live explorer data is complete: use the
  "Explorer" column of `ANSWER_KEY.md` for both interfaces, and record the
  deviation in `RESULTS.md`.
- **Re-recording:** record the ten transactions yourself
  (`txstory record ethereum <hash> -o CAPTURED/ethereum-<hash>.json`) and check
  them with `verify_answer_key.py`.

## Set up (once, about 5 minutes)

```bash
npm ci
npm run build
python3 study/score.py --self-test
python3 study/make_session_sheets.py 8 # P01..P08 → study/sessions, study/results (git-ignored)
python3 study/verify_answer_key.py --captured CAPTURED --evidence EVIDENCE --check   # needs the captured recordings
```

## Run a session (about 40 minutes)

```bash
TXSTORY_MODE=recorded TXSTORY_FIXTURES_DIR=CAPTURED npm start   # http://127.0.0.1:8787, offline
```

Then follow `FACILITATOR.md` with `sessions/P0N.md` open. The explorer condition
needs an internet connection. TxStory in recorded mode does not.

## After the sessions

```bash
python3 study/score.py                 # refuses to summarise if nothing is scored
```

Write up findings in `RESULTS.md`, including participants who struggled, and
amendments to the protocol, if any.

## Data handling

- **Nothing is collected automatically.** The app has no analytics, accounts,
  recording, or remote storage, and the kit adds none.
- **What is recorded:** an anonymous ID, a familiarity number, answers, times,
  and notes, typed by the facilitator into local CSVs under `study/results/`.
- **Results stay out of git.** That folder is git-ignored so results are never
  committed by accident.
- **Delete a participant's data** by deleting their `P0N.csv` and any rows about
  them in `issues.csv`.
- **Do not upload or share results** without the study owner's explicit decision.

## Known limitations

- **Sample size.** 5 to 8 people is exploratory. Results cannot be generalised and
  are not significance tests.
- **Task order** within a block is fixed: T1→T5.
- **Live versus recorded.** The explorer is live while TxStory is recorded. For
  T5 this means the two pages have different evidence, which is deliberate and
  documented in `ANSWER_KEY.md`.
- **Developer bias.** The kit was written by TxStory's developer. Tasks were
  chosen for diagnostic value, including T5, where TxStory's own figure is
  wrong, but a neutral reviewer of the tasks is still advisable.
